# 首屏群组空状态闪烁优化方案

## 问题描述

用户反馈每次首次进入小程序时，厨房页面会先显示"您当前未加入任何群组"的空状态，过一会儿才切换到正常的菜谱列表。虽然有开屏动画和加载动画，但动画结束后仍能看到"没有群组"的提示，体验很差。

## 根本原因分析

### 核心问题：阶段1只加载了菜谱数据，没有恢复群组信息

在 [pages/kitchen/index.js](file:///Users/a1/Documents/01Code/WeCt_Xcx/pages/kitchen/index.js) 的 `onShow` 生命周期中，数据加载分为两个阶段：

**阶段1（瞬时渲染，第 131-138 行）**：
```javascript
const lastGroupId = db.getLastGroupId();
if (lastGroupId) {
  db.setCurrentGroupId(lastGroupId);
  db.loadFromLocalCache(lastGroupId);  // 只加载菜谱、分类等业务数据
  this.setData({ loading: false });
  this.loadData();  // 渲染菜谱数据
}
```

`loadFromLocalCache` 从本地缓存加载了 `categories`、`recipes`、`orders`、`cart`，但**没有加载群组信息**（`groupsList` 和 `currentGroup`）。

**WXML 空状态判断（index.wxml 第 25-30 行）**：
```xml
<view wx:if="{{!currentGroup}}" class="empty-group ...">
  您当前未加入任何群组
</view>
<view class="main-content flex-row" wx:else>
  正常内容
</view>
```

由于 `currentGroup` 初始值为 `null`，阶段1渲染时 `currentGroup` 仍然是 `null`，所以会显示空状态。

**阶段2（后台刷新，第 151-153 行）**：
```javascript
await app.globalData.loginPromise;
await this.loadGroupsList();  // 这里才会设置 currentGroup
```

直到 `loadGroupsList()` 完成后，`currentGroup` 才被设置，此时才切换到正常内容。这中间的时间差就是用户看到的"闪烁"。

### 已有的缓存基础设施（未被充分利用）

[utils/db.js](file:///Users/a1/Documents/01Code/WeCt_Xcx/utils/db.js) 中已经有：
- `cacheGroupsList(groups)` / `getCachedGroupsList()` — 群组列表本地缓存（第 169-175 行）
- `setLastGroupId(groupId)` / `getLastGroupId()` — 上次使用的 groupId 持久化（第 159-167 行）

[pages/order/index.js](file:///Users/a1/Documents/01Code/WeCt_Xcx/pages/order/index.js) 第 63-80 行已经在使用 `db.getCachedGroupsList()` 来避免重复调用 getGroup 云函数，但 kitchen 页面的阶段1没有利用这个缓存。

## 优化方案

### 核心思路：阶段1同步恢复群组信息，彻底消除空状态闪烁

在 `onShow` 的阶段1中，不仅加载菜谱数据，还从本地缓存恢复 `groupsList`、`currentGroup`、`groupIndex` 和 `isAdmin`，确保首屏渲染时 `currentGroup` 不为 null，直接显示正常内容。

### 修改文件清单

| 文件 | 改动内容 |
|---|---|
| `pages/kitchen/index.js` | onShow 阶段1恢复群组信息；app.js 预加载群组缓存 |
| `app.js` | onLaunch 中增加群组列表缓存预加载 |

### 具体修改步骤

#### 步骤 1：kitchen 页面 onShow 阶段1恢复群组信息

**文件**：`pages/kitchen/index.js`

修改 `onShow` 中的阶段1逻辑（第 131-138 行）：

```javascript
// 阶段1：瞬时渲染本地缓存（不 await 任何网络）
const lastGroupId = db.getLastGroupId();
if (lastGroupId) {
  db.setCurrentGroupId(lastGroupId);
  db.loadFromLocalCache(lastGroupId);
  
  // 从本地缓存恢复群组列表和当前群组信息
  const cachedGroups = db.getCachedGroupsList();
  const currentGroup = cachedGroups.find(g => g._id === lastGroupId) || null;
  const groupIndex = cachedGroups.findIndex(g => g._id === lastGroupId);
  const myOpenid = (app.globalData.userInfo && app.globalData.userInfo.openid) || 
                   (wx.getStorageSync('userInfo') && wx.getStorageSync('userInfo').openid) || '';
  const isAdmin = currentGroup && currentGroup.ownerId === myOpenid;
  
  this.setData({
    loading: false,
    groupsList: cachedGroups,
    currentGroup: currentGroup,
    groupIndex: groupIndex > -1 ? groupIndex : 0,
    isAdmin: isAdmin
  });
  this.loadData(); // 同步从内存读，立即渲染
}
```

**说明**：
- 从 `db.getCachedGroupsList()` 读取缓存的群组列表
- 根据 `lastGroupId` 找到对应的 `currentGroup`
- 从本地存储的 `userInfo` 中获取 openid 来判断 isAdmin（因为 loginPromise 可能还没完成）
- 一次性 setData 所有相关字段，避免多次渲染

#### 步骤 2：app.js onLaunch 预加载群组列表缓存

**文件**：`app.js`

在 `onLaunch` 中，除了预加载菜谱数据，还可以确保群组列表缓存在本地（其实 kitchen 页面的 loadGroupsList 已经会缓存，这里只是保险起见）。

当前 app.js 第 14-19 行已有：
```javascript
// 预加载本地缓存，实现首屏瞬时渲染（同步，无网络开销）
const lastGroupId = db.getLastGroupId();
if (lastGroupId) {
  db.setCurrentGroupId(lastGroupId);
  db.loadFromLocalCache(lastGroupId);
}
```

无需修改 app.js，因为 `cachedGroupsList` 的读取是在 kitchen 页面的阶段1进行的，只要之前 loadGroupsList 调用过 `db.cacheGroupsList(groups)`，缓存就存在。

#### 步骤 3：兜底处理 — 加载状态下隐藏空状态

**文件**：`pages/kitchen/index.wxml`

为了防止极端情况（例如用户第一次安装后清除了缓存但 lastGroupId 还在），调整空状态的显示条件：

当前（第 25 行）：
```xml
<view wx:if="{{!currentGroup}}" class="empty-group ...">
```

改为：
```xml
<view wx:if="{{!currentGroup && !loading}}" class="empty-group ...">
```

**说明**：当 `loading` 为 true 时，即使 `currentGroup` 为空，也不显示空状态，而是显示骨架屏或加载状态。这样可以避免在数据加载过程中给用户错误的"未加入群组"的暗示。

#### 步骤 4：开屏期间确保 currentGroup 已恢复

**文件**：`pages/kitchen/index.js`

在 `runSplashWorkflow` 中，开屏结束后才显示内容。由于开屏期间会等待 `loadGroupsList()` 完成（第 280 行），所以开屏结束时 `currentGroup` 已经被设置了。

但为了双重保险，可以在开屏流程开始前也执行阶段1的缓存恢复，这样即使开屏超时（6秒超时降级），也能显示缓存的群组信息。

当前 `runSplashWorkflow` 第 276-290 行：
```javascript
const timeoutPromise = new Promise(resolve => setTimeout(resolve, 6000));
const loadPromise = (async () => {
  try {
    await app.globalData.loginPromise;
    await this.loadGroupsList();
  } catch (err) {
    console.error('[Splash] load error', err);
  }
})();
```

这部分逻辑已经在等待 loadGroupsList，所以开屏结束后 currentGroup 一定是有的。但超时情况下（6秒还没加载完），`loadGroupsList` 可能还没完成，此时显示的页面就会有空状态。

**优化**：在开屏流程开始前，先执行阶段1的缓存恢复（和 onShow 中一样的逻辑），这样即使超时，也能显示缓存内容。

在 `runSplashWorkflow` 开头（第 270 行之后）添加：
```javascript
// 开屏前先从本地缓存恢复数据，确保即使超时也能显示内容
const lastGroupId = db.getLastGroupId();
if (lastGroupId) {
  db.setCurrentGroupId(lastGroupId);
  db.loadFromLocalCache(lastGroupId);
  const cachedGroups = db.getCachedGroupsList();
  const currentGroup = cachedGroups.find(g => g._id === lastGroupId) || null;
  const groupIndex = cachedGroups.findIndex(g => g._id === lastGroupId);
  const userInfo = wx.getStorageSync('userInfo') || {};
  const isAdmin = currentGroup && currentGroup.ownerId === (userInfo.openid || '');
  
  this.setData({
    groupsList: cachedGroups,
    currentGroup: currentGroup,
    groupIndex: groupIndex > -1 ? groupIndex : 0,
    isAdmin: isAdmin,
    loading: false
  });
  this.loadData();
}
```

## 预期效果

| 场景 | 优化前 | 优化后 |
|---|---|---|
| 有本地缓存的冷启动 | 先显示"未加入群组"，1-3秒后切换到菜谱 | **直接显示菜谱，无空状态闪烁** |
| 开屏动画结束后 | 可能看到空状态闪烁 | **开屏结束后直接显示菜谱** |
| 首次使用（无缓存） | 显示空状态 | 显示骨架屏 + 加载中，不显示空状态文案 |
| 网络慢/超时 | 长时间显示空状态 | 显示本地缓存内容，后台继续加载 |

## 风险与注意事项

1. **缓存陈旧性**：群组名称、群主等信息可能与云端不一致，但后台刷新后会自动更新，对用户体验影响极小。
2. **用户信息未登录时**：阶段1中 isAdmin 的判断依赖本地存储的 userInfo，如果用户清除了缓存但 lastGroupId 还在，isAdmin 可能判断错误。但这只是显示问题（管理按钮的显示），后台刷新后会纠正。
3. **多群组切换**：切换群组时走 `onGroupChange` 逻辑，已经有缓存优先的处理（第 239-253 行），不受影响。
4. **极端情况兜底**：步骤3的 `!loading` 条件确保了在真正加载中不会误导用户。

## 验证步骤

1. **有缓存冷启动**：正常使用后杀进程，重新打开小程序，观察厨房页面是否直接显示菜谱，不出现"未加入群组"。
2. **开屏动画**：首次打开（清除 splashShown 标记），观察开屏结束后是否直接显示菜谱，无闪烁。
3. **无缓存首次启动**：清除所有缓存后启动，观察是否显示骨架屏/加载状态，而不是"未加入群组"。
4. **网络超时模拟**：模拟慢网络，观察是否先显示缓存内容，后台刷新后更新。
5. **群组切换**：切换群组时是否正常，切换后的数据是否正确。
6. **管理员权限**：管理员按钮是否正确显示（本地缓存时可能有误，但云端刷新后要正确）。
