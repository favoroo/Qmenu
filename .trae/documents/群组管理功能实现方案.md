# 群组管理功能实现方案

## 概述

在现有「Q 菜单」小程序的群组模块基础上，增加群组列表视图与单群组精细管理能力（修改群名、移除成员、转让群主、重新生成邀请码），使用户可在群组管理模块中管理每个群组。

## 当前状态分析

- `pages/group/index`（.js/.wxml/.wxss）目前仅管理"当前选中的单个群组"，通过 `db.getCurrentGroupId()` 获取，无群组列表视图。
- 厨房页 `pages/kitchen/index.js` 的 `goGroupManage()` 跳转到 `/pages/group/index`（不传 groupId）。
- 现有云函数各功能独立目录：`createGroup`、`getGroup`、`joinGroup`、`leaveGroup`、`disbandGroup`。
- `getGroup` 不传 groupId 时已返回用户所有群组（`groups` 数组），可作为列表数据源，无需改动。
- 群组数据结构：`{ _id, name, ownerId, inviteCode, members: [{openid, nickName, avatarUrl, role: 'owner'|'member'}], createdAt }`。
- 云函数统一模式：`cloud.init({ env: cloud.DYNAMIC_CURRENT_ENV })` + `getWXContext()` 取 OPENID + 返回 `{ success, errMsg, ... }`。
- 前端与前一页通信：通过 `getCurrentPages()` 获取前一页并调用其 `loadGroupsList()` 方法刷新。

## 提议改动

### 一、新增 4 个云函数（每个独立目录，含 index.js + package.json）

`package.json` 统一模板：
```json
{
  "name": "<函数名>",
  "version": "1.0.0",
  "dependencies": { "wx-server-sdk": "~2.6.3" }
}
```

#### 1. `cloudfunctions/updateGroupName/index.js`（修改群名）
- 入参 `{ groupId, name }`
- 权限：仅群主（`group.ownerId === OPENID`）
- 逻辑：校验登录/参数 → 取群组 → 校验群主 → `update({ data: { name: name.trim() } })` → 返回更新后的 `group`
- 设计原因：遵循现有"一功能一目录"模式

#### 2. `cloudfunctions/removeMember/index.js`（移除成员）
- 入参 `{ groupId, memberOpenid }`
- 权限：仅群主
- 约束：禁止移除群主（自己）；校验 `memberOpenid` 确为群内成员
- 逻辑：`members.filter(m => m.openid !== memberOpenid)` 后 `update` → 返回更新后的 `group`
- 数据清理：按需求约定，仅删 `members`，不动 `cart/orders`（保持现状）

#### 3. `cloudfunctions/transferOwner/index.js`（转让群主）
- 入参 `{ groupId, newOwnerOpenid }`
- 权限：仅群主
- 约束：禁止转给自己；校验目标为群内成员
- 逻辑：同时更新 `ownerId` 与 `members` 中两条 `role`（新群主 `owner`、原群主 `member`）→ 返回更新后的 `group`

#### 4. `cloudfunctions/regenerateInviteCode/index.js`（重新生成邀请码）
- 入参 `{ groupId }`
- 权限：仅群主
- 逻辑：复用 `createGroup` 的 `genInviteCode`（A-Z+0-9 共6位）与去重逻辑 → `update({ data: { inviteCode } })` → 返回更新后的 `group`
- 旧邀请码即刻失效（`joinGroup` 按 `inviteCode` 查询，旧码查不到即报错）

> 4 个函数均返回更新后的完整 `group`，前端可直接刷新本地状态，与 `createGroup/joinGroup` 返回 `group` 的模式一致。

### 二、修改 `pages/group/index.js`

**data 新增字段：**
- `viewMode: 'list'`（`'list'` | `'detail'`）
- `groupsList: []`（列表数据）
- `currentGroupId: ''`（来自 `db.getCurrentGroupId()`，用于列表高亮）
- `myOpenid: ''`（用于 wxml 角色判断）

**方法改动：**
- `onLoad(options)`：改为先 `loadGroupList()`；若 `options.groupId` 存在则 `openGroupDetail(options.groupId)`（深链支持）；初始化 `myOpenid` 与 `currentGroupId`
- 新增 `loadGroupList()`：调 `getGroup`（不传 groupId）→ `setData({ groupsList })`
- 新增 `openGroupDetail(gId)`：`setData({ groupId, viewMode: 'detail' })` + `loadGroupInfo(gId)` + `wx.setNavigationBarTitle({ title: 群名 })`
- 新增 `backToList()`：`setData({ viewMode: 'list', groupId: '', group: null })` + `loadGroupList()` + `wx.setNavigationBarTitle({ title: '我的群组' })`
- `loadGroupInfo(gId)`：保留现状，成功后额外同步导航标题为群名
- `onCreateGroup` / `onJoinGroup`：成功后 `setData({ groupId, group, isOwner, viewMode: 'detail' })` + `loadGroupList()` + `prevPage.loadGroupsList()`
- `doLeaveGroup` / `doDisbandGroup`：成功后改为 `backToList()`（含 `loadGroupList`）+ `prevPage.loadGroupsList()`
- 新增 `onEditGroupName()`：`wx.showModal({ editable: true, placeholderText, content: 当前群名 })` → 调 `updateGroupName` → `setData({ group })` + `loadGroupList()`
- 新增 `onRegenerateInviteCode()`：`wx.showModal` 二次确认（提示旧码失效）→ 调 `regenerateInviteCode` → `setData({ group })`
- 新增 `onRemoveMember(e)`：取 `dataset.openid/name` → `wx.showModal` 确认 → 调 `removeMember` → `setData({ group })`
- 新增 `onTransferOwner(e)`：取 `dataset.openid/name` → `wx.showModal` 确认（提示转让后变为成员）→ 调 `transferOwner` → `setData({ group, isOwner: false })`

### 三、修改 `pages/group/index.wxml`

顶层按 `viewMode` 拆为两块：

**列表视图（`viewMode === 'list'`）：**
- 无群组：沿用现有 `no-group-box` 空状态卡片（含创建/加入表单）
- 有群组：渲染群组卡片列表（群名、群主/协作者标签、成员数、当前群组高亮）+ 下方紧凑创建/加入区

**详情管理视图（`else`）：**
- 顶部「‹ 返回群组列表」按钮
- 群名+邀请码卡片：群主多出「编辑」「重新生成」入口
- 成员列表：群主视角下，非自己的成员显示「转让群主」「移除」操作
- 底部：解散（群主）/ 退出（成员），原样保留

### 四、修改 `pages/group/index.wxss`

新增样式（沿用既有配色 `#2D5A43`、卡片 `card` 圆角阴影、`#EF4444` 危险色）：
- `.group-list` / `.group-card`：列表卡片样式
- `.card-meta` / `.meta-text` / `.current-tag`：成员数与"当前群组"标签
- `.back-row` / `.back-btn`：返回列表按钮
- `.edit-btn` / `.regen-btn`：群主专属小文字按钮
- `.member-actions` / `.action-text.transfer`（绿色）/ `.action-text.remove`（红色）

### 五、无需修改的文件
- `pages/group/index.json`：动态标题通过 `wx.setNavigationBarTitle` 设置
- `pages/kitchen/index.js` / `index.wxml`：`goGroupManage()` 仍跳到列表视图，`loadGroupsList()` 仍被回调刷新
- `utils/db.js`：`getCurrentGroupId/setCurrentGroupId` 复用
- `getGroup/createGroup/joinGroup/leaveGroup/disbandGroup`：保持现状
- `app.json`：`pages/group/index` 已注册

## 权限校验要点

**服务端（4 个新云函数统一遵循）：**
1. `OPENID` 必须存在
2. `groupId` 必须存在；`doc(groupId).get()` 校验群组存在
3. 群主校验：`group.ownerId === OPENID`，否则拒绝
4. 业务约束：
   - `removeMember`：禁止移除群主，校验目标为成员
   - `transferOwner`：禁止转给自己，校验目标为成员，同时更新 `ownerId` 与 `role`
   - `regenerateInviteCode`：确保新码全局唯一
5. 可见性：依赖既有 `getGroup`（按 `members.openid` 过滤），无法操作非己所属群组

**前端（体验层）：**
- `isOwner` 控制管理按钮显隐
- 成员行「转让/移除」仅对群主视角下非自己的成员显示（`isOwner && item.openid !== myOpenid`）
- 所有危险操作二次确认；前端校验仅为体验，最终以服务端为准

## UI 交互流程

1. 厨房页点「管理群组」→ 进入群组页（列表视图，标题"我的群组"）
2. 无群组：展示空状态创建/加入卡片
3. 有群组：展示群组卡片列表 + 紧凑创建/加入区；点击卡片进入详情（标题切换为群名）
4. 群主管理操作：编辑群名、重新生成邀请码、移除成员、转让群主
5. 退出/解散：保留原交互；成功后返回列表视图并刷新
6. 返回：详情视图点「‹ 返回群组列表」回列表（并刷新）
7. 跨页刷新：创建/加入/退出/解散/改名后调 `prevPage.loadGroupsList()` 刷新厨房页

## 假设与决策

- 列表为默认入口（非直接进当前群详情），符合"管理每个群组"诉求；已预留 `options.groupId` 深链支持
- 不拦截系统返回键：详情→列表用页内按钮，系统返回键回厨房页（原生行为）
- `genInviteCode` 在 `createGroup` 与 `regenerateInviteCode` 各保留一份副本，与现状一致，不抽公共模块（避免过度设计）
- 成员管理不做额外数据联动清理（按需求约定，`removeMember` 仅删 `members`，`cart/orders` 保留）

## 验证步骤

1. **部署云函数**：在微信开发者工具中上传部署 4 个新云函数，确认上传成功
2. **列表视图**：用已加入多个群组的账号进入，确认列表展示全部群组、标签、成员数、当前群组高亮；无群组账号展示空状态
3. **详情进入**：点击列表项进入详情，标题切换为群名；点「返回群组列表」回列表并刷新
4. **修改群名**：群主点「编辑」→ 改名 → 详情与列表同步、厨房页下拉同步
5. **重新生成邀请码**：确认后新码替换；旧码 `joinGroup` 失败、新码可加入
6. **移除成员**：群主移除某成员 → 成员列表更新；被移除账号厨房页该群组消失
7. **转让群主**：角色标签互换、原群主管理按钮消失且底部变「退出」、新群主可见管理按钮
8. **权限校验**：协作者不显示管理按钮；模拟非群主调用云函数返回错误
9. **既有流程回归**：创建/加入/退出/解散正常，且创建/加入后进详情、退出/解散后回列表
10. **边界**：移除自己（按钮不出现）、转让给非成员（返回错误）、重生成后邀请码唯一性
