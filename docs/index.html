一些工程细节 Under the hood

为了「点开就能用」，
我们在背后多做了几步

基于微信小程序原生与云开发构建。数据按群组隔离，写入先给反馈，图片坏了会自己修。

/ 01

三层缓存，首屏不等网络

内存、本地存储、云数据库三层依次兜底。冷启动先用缓存把界面画出来，再静默校正，打开就是满的。

/ 02

乐观更新，失败自动回滚

点下去立刻有反馈，请求在后台完成。万一失败就安静地还原，不会留下一个半成品的购物车。

/ 03

群组级数据隔离

分类、菜谱、订单、评分全部挂在群组下。换一个群组就是另一套菜单，彼此不会串味。

/ 04

图片加载失败会自己修

云存储地址有有效期，过期时图片会静默失效。我们会在加载失败时回源重新解析，再安静地试一次。

/ 05

每天凌晨清理无用图片

定时云函数会回收不再被任何菜谱引用的图片，存储不会悄悄变胖。

/ 06

订阅消息，只提醒该做饭的人

下单时指定大厨，消息只发给他。不打扰其他人，也不会错过今天该谁下厨。
